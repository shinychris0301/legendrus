# Profile History story recap R2

The approved R1 scope is implemented in the existing production flow. Profile → History has a live localized **СЮЖЕТ / STORY** action. It opens the most advanced acknowledged scene in catalogue order, with Earlier/Later browsing, native Continue and Back. An empty eligible ledger shows a disabled **НЕТ ПРОЧИТАННЫХ СЦЕН / NO READ SCENES** action. Existing history statistics and paging remain available.

`StoryRecap.Read` projects the installed Chapter 1 catalogue against the production save: intro acknowledgement, or milestone acknowledgement plus that chapter/round's positive completion count. Unknown, archived/scoped, duplicate, unread and unearned entries are excluded without normalizing the ledger. The projection copies scene data for its local sequence; all 58 installed scenes and existing Russian/English lines are covered by Edit Mode verification. “Latest” is catalogue order because the existing save has no acknowledgement timestamps.

`ProductionStoryRecapView` uses a separate `StorySequenceRuntime` and the actual existing Dialogue prefab's line, scene and speaker providers. ScreenRouter opens it through the existing modal host. The originating Profile object stays alive, preserving its History section and page. Back or the final Continue closes that modal. Replaying the round-500 finale never dispatches its normal ChapterComplete route. The existing normal StoryService and development campaign ledger remain independent.

The reader gates input during transitions, blocks underlying Profile controls and rejects repeated same-frame actions. Its callbacks are retired on exit or another screen route. Recap does not select levels, consume energy, grant rewards, acknowledge scenes/chapter completion or persist player journals. Normal clock-based energy refresh continues independently. Full save/journal comparisons use a below-cap synthetic energy fixture so ordinary clock refresh is distinct from reader behavior.

Changed existing project inputs: ProductionProfileView.cs, ProductionProfileRuntime.cs, ScreenRouter.cs, ProductionProfilePrefabBuilder.cs, Profile.prefab and ProfileCutoverState.txt. Profile's owner, active prefab, view and cutover agree on **revision 13**. The active prefab changes only that revision; all serialized object IDs/references remain. Dynamic entry controls belong to ProductionProfileRuntime. Dialogue.prefab and its existing owner/view remain unchanged; the reader adds native controls to the instantiated page. Four new C# files and their four unique GUID metadata files provide the projection, reader and focused tests.

All original artwork, fonts and metadata, approved Splash, other prefabs, packages, settings, backend, Android guards and normal story/save services are preserved. No new Canvas/EventSystem, startup route, ScreenId, artwork, font distribution, catalogue or save migration. Exact source-font identity and physical readability remain unverified. This implementation follows [the approved bounded scope](../../ReturningPlayerReview/R1/ImplementationScope.md).
